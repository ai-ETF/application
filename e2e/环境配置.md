# E2E 环境配置：跑起来到底要配哪些东西

> **这份是「照着做」**：换一台机器、或者重装完环境，要把 E2E 从零跑起来，对着这份配。
> [README §2](README.md#2-跑之前必须满足的条件) 是「出了什么症状该查哪一条」——两边互相指。
> 后端（`ai-etf` 仓库）那边要配什么也一并写在这一份里。
>
> 私有的、本机才有的配置**不进 git**，所以这份文档就是它们的唯一载体：**新机器上，这是第一步**。

---

## 0. 总览：四类配置，只有第 1 类仓库里没有

| # | 配置 | 放哪 | 进 git 吗 |
|---|---|---|---|
| 1 | 小程序私有配置 | `application/src/project.private.config.json` | ❌ **不进，要自己建** |
| 2 | 前端接口地址 | `application/.env.development` | ✅ 进（本来就在仓库里） |
| 3 | 后端怎么起 | 不落文件，靠命令行带环境变量 | — |
| 4 | 本机环境 | `node_modules` 补丁 / 开发者工具 / 端口 | 补丁脚本进，其余是本机状态 |

**第 1 类为什么不进 git**：它是微信那套配置里的「个人层」，本来就是设计给每台机器放**自己的本地偏好**用的。
里面没有密钥，但提进仓库等于替所有人把本地偏好定死了。所以改成「不进仓库、照 §1 手建」。

## 1. `src/project.private.config.json` —— 唯一一个必须自己建的文件

### 1.1 放哪

```
application/src/project.private.config.json
```

⚠️ **必须在 `src/` 下。** 放仓库根目录**不生效** —— uni-app 编译时是相对「编译入口目录（`src/`）」
去拷这个文件的，放根目录它根本不会进产物 `dist/dev/mp-weixin/`，而微信开发者工具读的是**产物目录**。
（这条我们绕了很久，来龙去脉见 ai-etf 仓库的 `docs/e2e/07-小程序E2E环境配置说明.md` §3.3。）

### 1.2 内容（直接复制）

```json
{
  "appid": "touristappid",
  "libVersion": "3.16.1",
  "projectname": "application",
  "setting": {
    "urlCheck": false,
    "coverView": true,
    "lazyloadPlaceholderEnable": false,
    "skylineRenderEnable": false,
    "preloadBackgroundData": false,
    "autoAudits": false,
    "showShadowRootInWxmlPanel": true,
    "compileHotReLoad": true
  }
}
```

**真正起作用的只有两项**，其余是开发者工具自己写进去的默认值，跟着原样留着就行：

| 项 | 值 | 为什么 |
|---|---|---|
| `appid` | `touristappid` | 游客模式。用真 appid（`wx4345af65c586dd70`）的话，**只有被管理员加进「开发者」名单的微信账号**打得开，别人一跑就被拒；`touristappid` 谁 clone 下来都能跑，不看权限。代价是控制台会报一句 `gettestpublib Error 41002, appid missing` —— **实测不影响跑通**（成功的运行里也有它）。<br>要测跟 appid 绑定的能力（`wx.login` 的真实 code、云能力、真机发布）时才需要换成真 appid，一行的事，但先确认账号有权限。 |
| `setting.urlCheck` | `false` | 本地后端是 `http://localhost:8000`，不在合法域名白名单里。⚠️ 但**「必须关」这件事没被证实**：把它设回 `true`，整套 P4 照样全绿（含需要真实 HTTP 往返的 P4-02）。留着当**零成本保险**，别当成已证事实。 |

⚠️ `urlCheck` 只管**本地开发**的域名校验；发布后的域名校验由微信服务端强制，跟这个开关无关 → 关掉**不构成线上风险**。

### 1.3 少建了会怎样

- **项目根本打不开** —— 开发者工具拿 appid 去微信要权限被拒，CLI 直接退出。
- ⚠️ **而且报错是假的**：最后甩出来的是
  `Failed to launch Wechat web DevTools , please make sure http port is open`。
  **这句话跟端口一点关系都没有**，是 appid 权限问题。看到它先查 appid 和登录状态，**别去查端口**。
- 用例自己也会拦一道：`helpers/env.js` 的 `assertTouristAppId()` / `assertUrlCheckDisabled()`
  读的是**合并后**的生效值，对不上会让用例当场失败，而不是跑出一个莫名其妙的红。

### 1.4 怎么确认它真的生效了

```bash
# ① 编译（必须在 Windows 侧，见 §4.1）
npm run dev:mp-weixin

# ② 产物里得先有它
ls dist/dev/mp-weixin/project.private.config.json

# ③ 生效值要是「private 覆盖 public」之后的结果 —— 别只看 uni 生成的那份
node -e "const b=require('./dist/dev/mp-weixin/project.config.json');const p=require('./dist/dev/mp-weixin/project.private.config.json');console.log({...b.setting,...p.setting}.urlCheck, p.appid||b.appid)"
# 期望输出：false touristappid
```

## 2. 前端 `application/.env.development`

要确认的就一条：

```
VITE_API_BASE=http://localhost:8000
```

- **为什么它是关键**：`src/config/index.ts` 里 `API_BASE` 的**兜底值是生产地址**。
  这条没配，测试就会真的去打线上库、往生产写数据。
- 所以就算忘了也拦得住：每条用例开跑前都会调 `assertLocalApiBase()`（[helpers/env.js](helpers/env.js)），
  检查产物里的 `API_BASE` 是不是 `localhost` / `127.0.0.1` / `[::1]`，不是就**直接抛错拒绝运行**：
  `⛔ 构建产物打的是【非本地】后端，E2E 拒绝运行`。
- ⚠️ **这是前端自己的 `.env.development`**，跟后端 `ai-etf/.env`（放模型密钥的）是两回事，别混。
- 改完**要重新编译**才会进产物。

## 3. 后端怎么起（`ai-etf` 仓库）

### 3.1 带行情夹具启动

```bash
cd ai-etf
E2E_MARKET_FIXTURE="$PWD/docs/e2e/fixtures/market_snapshot.json" \
ENABLE_TEST_ENDPOINTS=1 \
  poetry run uvicorn server.app:app --port 8000
```

- **`E2E_MARKET_FIXTURE` 不能省**：本机连不上东财行情接口（**不是代码 bug**），
  不带夹具时行情/自选相关断言拿到的是**空数据**，看起来像用例写错了。
- **`ENABLE_TEST_ENDPOINTS=1` 跑 P1 必须带**：后端默认**不注册** `/api/portfolio/test/*`
  这组免登录端点（2026-10-13 起），不带它 P1 造数据的前置步骤会 404。改动的理由见
  `ai-etf/docs/e2e/01-页面与API调用关系.md` §5.4。
- **起没起对，看启动日志**：应出现 `哈希表构建完成，共 3 只ETF`；不带夹具是 **0 只**。
- 没带 `--reload`：**改了后端代码必须重启进程**才生效。

### 3.2 本地 Supabase 栈要在跑

登录/注册走的是 Supabase。栈没起 → 注册/登录 401 或直接失败。
最快的判断方法：跑一条 P4 用例（`npm run test:e2e -- p4-auth`），**能注册成功、能登录**，栈就是活的。

### 3.3 只有 P2（AI 对话）额外需要

后端要能连上**模型服务**（密钥在后端的 `.env` 里，我们不读内容）。
连不上时的表现是：bot 气泡渲染出兜底文案「抱歉，AI 服务未返回有效回复。」——
处置见 [README §6.7](README.md#67-p2-气泡里是抱歉或干脆是空的)。

## 4. 本机环境

### 4.1 必须在 **Windows** 侧执行

WSL 里跑会因为 `node_modules` 是 Windows 侧装的而报 rollup 错、或找不到 CLI。
固定跑法：

```powershell
powershell.exe -NoProfile -Command "Set-Location 'D:\C1\Have a try\etf\code\application'; npm run test:e2e -- p4-auth"
```

### 4.2 `node_modules` 补丁

```bash
npm run e2e:patch        # 打补丁（幂等）
npm run e2e:patch:check  # 只检查，不改
```

- 改的是 `node_modules` 里 **2 个文件共 4 处**，理由写在脚本头：
  [`e2e/patches/apply-node-modules-patches.js`](patches/apply-node-modules-patches.js)。
- 一句话：**Node ≥ 18.20.2 起，`spawn` 一个 `.bat` 不加 `shell: true` 会抛 EINVAL**（CVE-2024-27980 的加固），
  而本机路径 `D:\C1\Have a try\...` **同时含空格和中文**，加了 `shell: true` 还得自己补引号 —— 这 4 处是一套，不能只打一半。
- **重装 `node_modules` 后补丁会丢**，重跑一次即可（`npm run test:e2e` 会自动带上）。
- 故意**不做 `postinstall`**：这两个文件只有 E2E 才走到，不该让日常开发的人也承担副作用。

### 4.3 微信开发者工具

| 项 | 值 |
|---|---|
| 路径 | `D:\Program Files (x86)\Tencent\微信web开发者工具\cli.bat` |
| 版本 | **Stable v1.06.2504040**（本机实测） |

- 路径**已写死在** [`jest.e2e.config.js`](../jest.e2e.config.js) 的 `executablePath` 里 —— 因为
  uni-automator 的默认查找路径是 **C 盘**那个，本机装的不是那儿。
- 换版本前先读 `ai-etf/docs/e2e/04-工具选型.md` §5.3（有版本相关坑的记录）。
- 工具要**处于已登录状态**。

### 4.4 端口

| 用途 | 端口 |
|---|---|
| uni-automator 自己监听 | **9520** |
| 传给开发者工具的 `--auto-port` | **9420** |

**两个必须错开**。卡在 `Failed to connect to runtime` 时，先杀残留的开发者工具进程 ——
上一轮被打断的运行会把 9420 一直 LISTENING 着不放，下一轮就撞上它自己。
处置见 [README §6.1](README.md#61-failed-to-connect-to-runtime--wechat-web-devtools-not-found)。

## 5. 验收清单

配完逐条打勾，全对再谈跑用例：

- [ ] `application/src/project.private.config.json` 已建（在 `src/` 下），§1.4 那行命令输出 `false touristappid`
- [ ] `application/.env.development` 里 `VITE_API_BASE=http://localhost:8000`，且**已重新编译**

- [ ] 本地 Supabase 栈在跑（能注册/登录）
- [ ] 在 **Windows** 侧执行，`npm run e2e:patch:check` 通过
- [ ] 开发者工具装在 §4.3 那个路径、且已登录
- [ ] 没有残留的 `wechatdevtools` 进程占着 9420
- [ ] 只有跑 P2 时，额外要：后端能连上模型服务

都打勾了就跑：`npm run test:e2e -- p4-auth`（**按文件名跑**，别不带文件名 —— 那会把 P2 一起带上，真打模型、约多花 95 秒）。
